## 4.5 Not tested / limits — read before relying on this

* **Double-click `file://` launch was not verified in this environment** (the preview pane substitutes a static snapshot for local files). All testing was over `http://127.0.0.1`. The app uses only classic relative `<script>` tags (no modules, no fetch), so it is expected to work from a double-click in Chrome/Edge, but this has not been observed.
* **Browsers:** only one Chromium-based browser (Chrome 152 engine inside the Claude desktop app). Not run on Firefox, Safari, or older Edge.
* **Real Excel files:** XLSX tests use files generated by the test suite (valid OOXML, but not authored by Excel). Excel/Google-Sheets/WPS exports can contain features not exercised (rich-text cells, merged cells, hidden sheets, custom date formats). **Please test with 2–3 of the client's actual sheets (fictionalised) before go-live**; mapping templates should be fixed once the real layouts are known (OQ-19).
* **Responsive:** 375 px verified programmatically + screenshots; 768 px tablet and 1100 px breakpoints were not run separately; desktop reviewed at ~1000 px and a 1366 px emulation (screenshot crop only).
* **Not tested at all:** accessibility audit (screen reader, keyboard-only), performance with the 20,000-row import cap, browsers with storage disabled (logic suite covers quota failure only), printing, localisation/RTL.
* **Not testable in a prototype:** authentication, authorisation (roles are a UI demo), multi-user concurrency, data durability beyond one browser profile, encryption, server-side audit — these require the production system (doc 06).
* **Business-rule correctness** is only as good as V6: every assumption (doc 05) is tested for *consistency* (the same stage set drives card, report and export) but cannot be validated without the client's confirmation.

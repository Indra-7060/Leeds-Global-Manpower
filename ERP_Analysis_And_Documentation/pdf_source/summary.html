Leads Global ERP — Final Version

Short guide in simple English · Built from the client's latest reference (V8.7) · Data in this guide is fictional
Important — please read. This is a demonstration that works in one web browser on one computer. The data is saved inside that browser. It is not secure, not shared between people, and has no login or user roles. It can be lost if the browser's data is cleared. Please do not type real passport, QID or bank details into it. Use Download backup often.

1. What it does

The ERP manages recruitment for three divisions. Each division has its own steps, its own forms and its own dashboard. Every number on a dashboard is calculated from the records that were entered — nothing is typed in by hand.

To open it: double-click index.html in the folder Leads_Global_ERP_Final. No installation and no internet are needed.

2. The three divisions and their workflows

Blue-Collar
Client → Order → Overseas Agency → Agency Allocation → Candidate → Recruitment Stages → Interview → QVC → RTP → Visa → Ticket → Arrival → Deployment → Handover → Accounts
Domestic
Sponsor → Worker Requirement → Worker Registration → Recruitment Progress → Ticket / Arrival → Sponsor Handover → 9-month Warranty → Complaint / Replacement / Refund
Corporate
Company → Job Requirement → Candidate → Interview → Selection → Offer → Joining → Placement Fee / Accounts

The divisions are kept apart. A Domestic worker cannot be given a Blue-Collar stage such as Deployed, and a Blue-Collar record cannot be linked to a Domestic sponsor.

4. How to enter data

  1. Choose the division in the left menu.
  2. Add the client / sponsor / company, then the order (requirement).
  3. Blue-Collar only: add the agency and an allocation (agency + order + quantity + fee per deployed worker).
  4. Add the candidates. Each one starts at CV Received.
  5. Every day, record Daily Updates: pick the candidate, the date, the new stage, who did the work, what was done, and the next follow-up with its due date. The system then moves the candidate, fills the matching date (for example, Deployed fills the verified deployment date), and keeps the full history.
  6. Add interviews, tickets, documents and payments as they happen.

The forms check your entries: required fields, valid dates, numbers, links to existing records, and duplicates. Mistakes are shown under the field. A record that other records depend on cannot be deleted.

5. How statuses and numbers are calculated

ItemRule
Stage countersCurrent: candidates who are at that stage now. (Ever reached): candidates who were at that stage at any time.
Verified deploymentA daily update to Deployed sets the verified deployment date. Only these workers count for agency fees.
Agency fee earnedVerified deployed workers × the fee in the allocation.
Agency fee outstandingEarned minus payments linked to that allocation. The system warns if more workers are deployed than were allocated.
Warranty startThe sponsor handover date. A daily update to Handed Over records it and creates the warranty automatically.
Warranty endStart + 9 months (calendar months; 31 May + 9 months = 28 February). It is always calculated, never typed.
Warranty active / expiredActive while the end date is today or later (the end date is the last covered day). Expired after that. "Expiring soon" = 30 days or less left.
Open complaintA complaint reason is recorded and the claim is not Resolved.
Corporate placement fee0.5 month, 1 month, or a custom amount, using the candidate's salary. Earned when the candidate has Joined. Due date = joining date + the months set on the job requirement. Outstanding = fee − payments received.
Follow-upThe next action of a candidate's latest update. It is overdue when its due date has passed.

6. Where the dashboard numbers come from

  • Counts (clients, orders, candidates, interviews, tickets, documents): the number of saved records.
  • Stage cards and the division table: candidates grouped by their current stage; "—" means that stage does not exist in that division.
  • Money cards: calculated from allocations, verified deployments, placement fees and the payments entered in Accounts.
  • Warranty cards: calculated from today's date and each warranty's end date and complaint.
  • Alerts (bell icon): overdue follow-ups, open complaints, warranties ending soon, overdue fees — all live.

Click any card to see exactly which records make up the number. (Tested: 34 of 36 clickable cards match their list exactly; the other two are totals of quantities and open the source orders.)

7. Backup, import and export

  • Backup / Restore (Settings): one JSON file with all records, history and uploaded documents. A backup from another project, or a damaged file, is refused.
  • CSV import: download the template, fill it, upload it. You see a preview first — which rows will be added, which are duplicates, which are rejected and why. Nothing is saved until you confirm.
  • CSV export: every list and report can be exported.

8. Major limitations

  • Single browser, single computer; no sharing, no login, no roles, no encryption — not a secure or multi-user system.
  • Designed for hundreds of candidates. At about 2,000 candidates the data passes the browser's storage limit (about 5 MB).
  • No connection to accounting, e-mail, SMS or government systems. No artificial-intelligence features.
  • Tested in Chrome/Edge engines only. Not tested on Safari, Firefox or real phones.
  • A real system needs a server database, sign-in, permissions, server-side checks, secure file storage and backups. The code is organised so these can be added (the storage part is separate), but they are not built.

9. Questions for the client (the system uses a safe default until answered)

  1. Which of the 17 stages belong to each division? (A sensible set per division is used now.)
  2. What exactly makes a deployment "verified"? (A daily update to Deployed.)
  3. Must the warranty always start on the verified handover date, or can it be set separately? (Handover date by default; any difference is flagged.)
  4. Is the last day of the warranty still covered? Which claim statuses are allowed? (Yes; Active, Open, Resolved, Expired.)
  5. Corporate fee: confirm the basis options, when it is earned, and VAT. (Earned at joining; no VAT.)
  6. Do Domestic or Corporate use overseas agencies? Do Blue-Collar or Corporate have a warranty? (No, as in the reference.)
  7. Roles and security rules for the real system; old V6 modules (visits, demand letters, credentials, costing) — still needed?
